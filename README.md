Оценка временной сложности реализованных алгоритмовВ рамках лабораторной работы была проведена оценка вычислительной сложности следующих алгоритмов в зависимости от размера входных данных (n):Поиск суммы и поиск максимального элемента — O(n) (Линейная сложность)Для выполнения данных операций необходимо однократно перебрать весь массив элементов. Количество базовых операций растет прямо пропорционально размеру входных данных n, что соответствует линейной временной сложности.Алгоритм поиска пар элементов — O(n^2 ) (Квадратичная сложность)Поиск всех возможных пар реализуется с использованием вложенных циклов, где для каждого из n элементов выполняется полный проход по всему списку из n элементов. Итоговое число операций пропорционально n×n=n^2, что определяет квадратичную сложность.Бинарное (быстрое) возведение в степень — O(log(n) ) (Логарифмическая сложность)На каждом шаге показатель степени n уменьшается вдвое за счет свойства четности. В результате количество необходимых умножений растет как log(n), что обеспечивают высокую скорость работы при больших n.Выбор линейных осей координат позволяет наглядно продемонстрировать эффект выполаживания графика O(log n ), подчеркивая высокую эффективность алгоритма binary_pow при работе с большими значениями n.Наклон на log-log графике определяется линейной регрессией зависимости \(\log T(n)\) от \(\log n\). Поскольку для \(T(n)=Cn^p\) выполняется \(\log T(n)=\log C+p\log n\), коэффициент наклона \(p\) соответствует показателю степени в асимптотической оценке сложности.И это как раз математически объясняет, почему 1.01 → \(O(n)\), а 2.01 → \(O(n^2)\).
